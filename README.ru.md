# Sync and MCP — сервер

[English](README.md) | **Русский**

Сервер для плагина Obsidian [Sync and MCP](https://github.com/nejroseld/sync-and-mcp): хранит
зашифрованные blob'ы vault'ов (sync), принимает опубликованный plaintext «AI Available», отдаёт
его по MCP (streamable HTTP) и строит поиск (FTS5 + эмбеддинги).
Контракт описан в `docs/API.md`, архитектура в `docs/ARCHITECTURE.md`.

Код сервера:

```bash
git clone https://github.com/nejroseld/sync-and-mcp-backend.git
cd sync-and-mcp-backend
```

Технические имена остались от рабочего названия проекта obsi-mcp: Python-пакет `obsi_server`,
команда `obsi-server`, сервис `obsi-mcp.service`, каталоги `/opt/obsi-mcp` и `/var/lib/obsi-mcp`,
переменные `OBSI_*`. Они не меняются, чтобы обновление уже установленных серверов проходило без
миграции.

## Что видит сервер

- Синхронизируемые файлы шифруются на устройстве через rclone crypt и приходят **зашифрованными**.
  Пароль шифрования, имена и содержимое файлов сервер не знает.
- Заметки, открытые пользователем для ИИ, публикуются **открытым текстом**: сервер индексирует их
  и отдаёт MCP-клиентам. В плагине доступ ИИ по умолчанию выключен.
- MCP-клиенты не пишут в vault напрямую. Предложенная правка ставится в очередь, и Obsidian
  пользователя применяет её, только если это разрешают правила ИИ и заметка не изменилась.

## Несколько пользователей

Каждый пользователь регистрирует отдельную учётную запись и создаёт собственные vault'ы.
Администратор выдаёт одноразовое приглашение; для второго и следующих пользователей повторяет
команду с другим именем:

```bash
obsi-server --data-dir ./data admin create-invite --name alice
obsi-server --data-dir ./data admin create-invite --name bob
obsi-server --data-dir ./data admin list-users
```

Код показывается один раз. Человеку нужны два значения: адрес сервера и код, поэтому
пересылайте их одним сообщением:

```
Приглашение в Sync and MCP для alice
Сервер: https://203-0-113-10.sslip.io
Код: inv_...
В Obsidian: Sync and MCP → «У меня есть приглашение», вставьте это сообщение целиком.
```

Готовое сообщение печатают `manage-vps.sh` (пункт меню «Пользователи и приглашения»),
`local.sh` и `install-vps.sh` (для первого приглашения). Плагин берёт из вставленного текста
первый http(s)-адрес и код `inv_...`, подписи строк значения не имеют. Затем пользователь
задаёт логин и пароль, создаёт свой серверный vault и отдельный пароль шифрования.
При следующем подключении выбирает «Войти». Пользователь видит только свои vault'ы и те,
к которым администратор явно выдал доступ. В плагине администратор может создавать
приглашения и смотреть список учётных записей во вкладке «Сервер».

После входа account session можно использовать в `/api/v1/tokens` для выпуска device- или
MCP-токенов с явными grants на собственные vault'ы. Делегированные токены не получают
implicit owner access, не могут создавать vault'ы и управлять токенами. Смотрите
`docs/API.md` для полного контракта.

На новой установке `local.sh` и `install-vps.sh` создают admin-токен и первое приглашение.
На уже установленном сервере данные и старые токены сохраняются; для новых пользователей
создайте приглашения командой выше (для VPS используйте `--data-dir /var/lib/obsi-mcp`
и пользователя сервиса). Общие vault'ы и токены с грантами продолжают работать.

Зависимости: Python 3.11+, `fastapi`, `uvicorn`, `httpx`. Для S3 установите `pip install -e '.[s3]'`.
Всё остальное стандартная библиотека
(sqlite3 с FTS5). `numpy` необязателен: если установлен, косинус считается быстрее.

## Установка на Ubuntu VPS

### С компьютера пользователя (рекомендуется)

Нужны VPS с Ubuntu 22.04 или новее и данные для входа из письма хостинга. На компьютере
должны быть `ssh` и `tar` (в macOS и Linux они уже есть; в Windows запускайте из WSL или Git Bash).
Из каталога репозитория:

```bash
./manage-vps.sh                 # или сразу с адресом: ./manage-vps.sh root@203.0.113.10
```

Первый запуск проводит через четыре шага:

1. **Сервер.** Адрес можно вставить в любом виде: `203.0.113.10`, `ubuntu@host:2222`,
   `ssh root@host -p 2222`. Пользователь по умолчанию `root`, порт `22`.
2. **Подключение.** Пароль SSH вводится один раз: скрипт держит одно общее соединение
   на всю сессию. При первом подключении к новому серверу скрипт показывает отпечатки его
   SSH-ключа и ждёт подтверждения, что они совпадают с панелью или консолью хостинга
   (`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`); без подтверждения пароль не вводится.
   Если пользователь не `root`, один раз запрашивается пароль `sudo` (он
   хранится только в памяти скрипта). Затем скрипт создаёт ключ `~/.ssh/obsi_mcp_ed25519`
   (права `0600`; при запущенном ssh-agent можно задать парольную фразу) и добавляет его на сервер, поэтому следующие запуски обходятся без пароля. Если сервер
   пускает только по ключу, скрипт попросит путь к ключу от хостинга.
3. **HTTPS-адрес.** По Enter сервер получает бесплатный адрес вида `203-0-113-10.sslip.io`
   (DNS-сервис, который возвращает IP из имени), свой домен с A-записью на IP сервера тоже
   подойдёт. Скрипт проверяет DNS, ставит Caddy и получает сертификат Let's Encrypt
   (`scripts/setup-https.sh`; при активном `ufw` открывает порты 80 и 443). Ответ «нет»
   оставляет сервер без HTTPS: тогда он доступен только через SSH-туннель из меню.
4. **Установка.** Код загружается на VPS и ставится через `install-vps.sh` без вопросов
   (S3 не настраивается). В конце скрипт проверяет `/api/v1/health` и показывает
   первое приглашение в виде готового сообщения с адресом сервера и кодом; admin-токен
   выводится на экран только после отдельного подтверждения.
   Его можно переслать или вставить в Sync and MCP самому: «У меня есть приглашение».

Последующие запуски открывают меню. По Enter выполняется пункт по умолчанию (обновление
сервера). В меню также есть данные для подключения, состояние и логи, домен и HTTPS,
SSH-туннель, S3, пользователи и приглашения, отключение входа по паролю и переход на другой сервер.
Пункт «Пользователи и приглашения» показывает зарегистрированных пользователей (дата, число
vault'ов и токенов) и неиспользованные приглашения, затем спрашивает имя и печатает сообщение
для пересылки; можно создать несколько приглашений подряд, пустое имя возвращает в меню. При обновлении
настроенный S3 сохраняется. Параметры подключения хранятся в `~/.config/obsi-mcp/vps.conf`
с правами `0600`, пароли туда не пишутся. Журнал последней ошибки сохраняется в
`~/.config/obsi-mcp/last-error.log`. Переменная `NO_COLOR=1` отключает цвета и анимацию.

Язык интерфейса берётся из `--lang ru|en` (запоминается в `vps.conf`), переменной `OBSI_LANG`
или системной локали; по умолчанию английский. Строки лежат в `scripts/i18n/<язык>.sh`.
Чтобы добавить язык, скопируйте `en.sh` в `<код>.sh` и переведите значения; ключи, которых
нет в переводе, показываются по-английски.

Пункт «Вход на сервер только по ключу» отключает парольную и keyboard-interactive
SSH-аутентификацию для всех пользователей VPS; включайте его, только если у остальных
тоже настроен вход по ключу. После изменения скрипт проверяет новый SSH-сеанс. Если
подтвердить вход не удаётся, прежние настройки SSH восстановятся через две минуты.

### Непосредственно на VPS

Из каталога этого репозитория:

```bash
sudo ./install-vps.sh
# другой локальный порт: sudo env OBSI_PORT=9000 ./install-vps.sh
```

Скрипт устанавливает Python 3.11+ и создаёт с нуля `/opt/obsi-mcp/venv`. Зависимости ставятся
только из `requirements.lock` (или `requirements-s3.lock` при настроенном S3) с проверкой хешей,
поэтому повторный запуск даёт тот же набор пакетов. Код приложения копируется в `/opt/obsi-mcp/src`.
Скрипт создаёт отдельного
системного пользователя и сервис `obsi-mcp.service` (`PrivateTmp`, `MemoryHigh=768M`,
`MemoryMax=1G`, `TasksMax=128`; лимиты памяти меняются через `OBSI_MEMORY_HIGH` и
`OBSI_MEMORY_MAX`). Данные хранятся в `/var/lib/obsi-mcp`.
При первой установке создаются admin-токен и первое приглашение; прочитать их можно командой
`sudo cat /var/lib/obsi-mcp/TOKENS.txt`; на экран приглашение выводится, только если вывод
идёт в терминал. Приглашение действует 7 дней. В сообщении-приглашении там стоит заглушка
`<your server address>`: замените её публичным HTTPS-адресом перед пересылкой. Повторный запуск обновляет приложение и сервис, сохраняя
данные и ранее выданные токены. Настройки S3 и необязательные ключи доступа сохраняются
в `/etc/obsi-mcp/s3.env` с правами `0600`; при отсутствии этого файла используется только
локальное хранилище.

Проверка: `curl http://127.0.0.1:8765/api/v1/health`; состояние:
`sudo systemctl status obsi-mcp`; логи: `sudo journalctl -u obsi-mcp -f`.
Без токена `/api/v1/health` с внешнего адреса отвечает только `{"ok": true}`; версия и
модули видны с localhost или с любым действующим токеном.
Сервис слушает только `127.0.0.1`. Для доступа с другого устройства настройте reverse proxy
с HTTPS на VPS и укажите его публичный URL в плагине и MCP-клиенте (`/mcp`).

## Самый быстрый запуск: `./local.sh`

```bash
./local.sh
```

При первом запуске создаёт `.venv`, ставит зависимости, заводит admin-токен и первое
приглашение и пишет их в `data/TOKENS.txt`; в терминал приглашение печатается и готовым
сообщением. Зависимости ставятся из `requirements.lock` с проверкой хешей.
Каталог данных и его содержимое доступны только владельцу (`0700` для каталогов,
`0600` для файлов), в том числе при повторном запуске со старыми данными.
Если старый `TOKENS.txt` раньше был доступен другим локальным пользователям,
отзовите все сохранённые в нём токены и выпустите новые: изменение прав не отзывает секреты.
Затем запускает сервер на `http://127.0.0.1:8766`. Повторные запуски просто стартуют сервер.
Переопределить: `OBSI_PORT=9000 OBSI_HOST=0.0.0.0 OBSI_DATA_DIR=~/obsi-data ./local.sh`.
Для локального S3 задайте `OBSI_S3_BUCKET` (или `s3_bucket` в файле `OBSI_CONFIG`) и при необходимости `OBSI_S3_REGION`,
`OBSI_S3_ENDPOINT`, `OBSI_S3_PREFIX`, `OBSI_S3_THRESHOLD_MB` и стандартные переменные
учётных данных AWS перед запуском `./local.sh`.

## Запуск на своей машине (пошагово)

Сценарий: сервер и Obsidian на одном компьютере. Нужен Python 3.11+ (`python3 --version`).

**1. Забрать код:**

```bash
git clone https://github.com/nejroseld/sync-and-mcp-backend.git ~/sync-and-mcp-backend
cd ~/sync-and-mcp-backend
```

Если переносите уже работающий сервер с другой машины, скопируйте его каталог вместе с `data/`: так сохранятся уже созданные vault'ы и токены
(см. `data/TOKENS.txt`); тогда шаг 4 можно пропустить.

**2. Установить зависимости в venv:**

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -e .            # fastapi, uvicorn, httpx; numpy по желанию: pip install -e '.[fast]'
```

**3. Запустить сервер** (терминал оставить открытым, остановка — Ctrl+C):

```bash
obsi-server --data-dir ./data serve --port 8766
# проверка из другого терминала:
curl http://127.0.0.1:8766/api/v1/health
```

По умолчанию сервер слушает только `127.0.0.1` — для Obsidian на той же машине этого достаточно.
Для телефона в локальной сети: `--host 0.0.0.0` и открыть порт в firewall
(`sudo firewall-cmd --add-port=8766/tcp`).

**4. Создать admin-токен и приглашение** (в другом терминале, с тем же `--data-dir`; сервер можно не
останавливать):

```bash
. .venv/bin/activate
obsi-server --data-dir ./data admin create-token --kind admin --name root
obsi-server --data-dir ./data admin create-invite --name alice
```

Токены показываются один раз — сохраните их.

**5. Плагин в Obsidian:** установите [Sync and MCP](https://github.com/nejroseld/sync-and-mcp)
через BRAT (`nejroseld/sync-and-mcp`) или скопируйте `main.js`, `manifest.json`, `styles.css`
из релиза плагина в `<vault>/.obsidian/plugins/sync-and-mcp/` и включите его в Settings → Community plugins. В мастере плагина выберите
«У меня есть приглашение» и вставьте адрес `http://127.0.0.1:8766` вместе с кодом приглашения
(или всё сообщение целиком), затем задайте логин и пароль, создайте vault и введите отдельный
пароль шифрования.

**6. MCP в Claude Code:**

```bash
claude mcp add --transport http obsi http://127.0.0.1:8766/mcp --header "Authorization: Bearer <mcp-токен>"
```

**Отладка:** `curl -v http://127.0.0.1:8766/api/v1/health` — сервер жив;
`curl -H "Authorization: Bearer <device-токен>" http://127.0.0.1:8766/api/v1/me` — токен валиден.
`connection refused` — сервер не запущен или другой порт; `401` — неверный/отозванный токен.

## Запуск (кратко)

```bash
python3 -m obsi_server --data-dir ./data serve --host 0.0.0.0 --port 8765
# или: pip install -e . && obsi-server --data-dir ./data serve
```

Все команды (`serve` и `admin ...`) должны использовать один и тот же каталог данных
(`--data-dir` или `OBSI_DATA_DIR`; по умолчанию `./obsi-data` относительно текущей папки).
При прямом запуске сервер требует закрытый каталог данных (`chmod 700 КАТАЛОГ`);
`local.sh` исправляет права старого каталога автоматически.

Конфигурация через переменные окружения (или TOML-файл, путь в `OBSI_CONFIG`, секция `[server]`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `OBSI_DATA_DIR` | `./obsi-data` | sqlite-база и блобы (`vaults/<vid>/blobs/<sha256(key)>`) |
| `OBSI_HOST` / `OBSI_PORT` | `127.0.0.1` / `8765` | адрес |
| `OBSI_FEATURES` | `ai,mcp,rag` | включённые модули (`all`, `none`); `mcp` и `rag` требуют `ai` |
| `OBSI_MAX_BODY_MB` | `200` | лимит для загрузки зашифрованных файлов (тело пишется во временный файл в `DATA_DIR/tmp`, не в память); JSON API ограничен 1 MiB, вход и регистрация — 16 KiB, MCP — 8 MiB |
| `OBSI_MAX_AI_FILE_MB` | `32` | лимит одного файла AI Available (держится в памяти и в SQLite) |
| `OBSI_VAULT_QUOTA_MB` | `10240` | квота vault'а: шифротекст + AI Available + ожидающие MCP-правки; `0` — без квоты; превышение → `507 quota_exceeded` |
| `OBSI_MAX_CONCURRENT_UPLOADS` | `4` | одновременных загрузок больше 1 MiB; остальные ждут очереди |
| `OBSI_SYNC_REQUESTS_PER_MINUTE` | `6000` | предел запросов на авторизованный токен в минуту; увеличьте для особенно интенсивной синхронизации |
| `OBSI_RAG_WORKER` | `1` | фоновый поток эмбеддингов |
| `OBSI_CORS_ORIGINS` | `app://obsidian.md,capacitor://localhost,http://localhost` | явный список origin через запятую; `*` не принимается |
| `OBSI_API_DOCS` | `0` | `1` включает `/docs`, `/redoc`, `/openapi.json` (только для разработки) |
| `OBSI_SESSION_TTL_DAYS` / `OBSI_SESSION_IDLE_DAYS` | `180` / `30` | срок жизни сессии после входа и срок без использования; на пользователя живёт не больше 10 сессий |
| `OBSI_INVITE_TTL_DAYS` | `7` | срок действия приглашения |
| `OBSI_EMBEDDING_ALLOW_PRIVATE` | `0` | `1` разрешает `http://` и частные адреса для эмбеддингов (локальный Ollama); иначе только публичный `https` |
| `OBSI_S3_BUCKET` | не задан | бакет для вложений больше порога; нужны учётные данные boto3 |
| `OBSI_S3_THRESHOLD_MB` | `10` | порог выгрузки файлов, кроме `.md` |
| `OBSI_S3_REGION` / `OBSI_S3_ENDPOINT` / `OBSI_S3_PREFIX` | не задан / не задан / `obsi` | параметры S3 |
| `OBSI_S3_SSE` / `OBSI_S3_KMS_KEY_ID` | `auto` / не задан | шифрование объектов на стороне S3: `AES256`, `aws:kms`, `none`; `auto` — `AES256` для AWS, `none` при своём endpoint |

Пример TOML: `[server]\ndata_dir="/srv/obsi"\nfeatures=["ai","mcp"]\nmax_body_mb=500`.

Запросы входа ограничены по IP и имени аккаунта; регистрация — по IP. Для MCP
действуют отдельные ограничения на вызовы и поиск, для переиндексации и очистки AI —
отдельные лимиты. При превышении сервер отвечает `429` с `Retry-After`. Счётчики
хранятся в SQLite и действуют для нескольких процессов, использующих одну базу.

Сервер говорит по HTTP; для доступа из интернета ставьте за reverse proxy с TLS.
Настройка S3 и поведение файлов описаны в [docs/S3.md](docs/S3.md).

Для выдачи пользователю доступа администратор создаёт одноразовое приглашение в плагине
или через `POST /api/v1/admin/invites`. Пользователь вводит код, логин и пароль в мастере
подключения плагина и затем создаёт собственный vault. Старые device-токены и гранты
продолжают действовать; подробности в [docs/API.md](docs/API.md).

## Быстрый старт

```bash
python3 -m obsi_server --data-dir ./data admin create-token --kind admin --name root
python3 -m obsi_server --data-dir ./data admin create-invite --name alice
python3 -m obsi_server --data-dir ./data admin list-users
```

Для общей папки или MCP-клиента можно отдельно создать vault и токен с грантами через CLI
или admin REST API (`/api/v1/admin/...`).

Другие команды: `list-invites`, `revoke-invite INVITE_ID`, `list-vaults`, `list-tokens`, `revoke TOKEN_ID`, `grant TOKEN_ID --vault V --ops a,b`,
`rag-enable V`, `rag-disable V`, `reindex V`,
`set-embedding --base-url https://api.example.com/v1 --model text-embedding-3-small --api-key-file ~/emb.key`
(файл ключа с правами `0600`; `--api-key-prompt` спрашивает ключ без эха, `--clear-api-key` удаляет его).
Не переданные параметры не меняются. Ключ в аргументах командной строки не принимается: он
виден в списке процессов и истории shell. Адрес эмбеддингов должен быть публичным `https`:
сервер проверяет адрес при сохранении и при каждом подключении, не следует редиректам и
не использует `HTTP_PROXY`. Для локального Ollama (`http://localhost:11434/v1`) запустите
сервер с `OBSI_EMBEDDING_ALLOW_PRIVATE=1`.
Смена `model` или `base-url` сбрасывает векторы, индекс перестраивается в фоне (работающий сервер
подхватывает изменения из CLI в течение ~10 секунд).

В эмбеддинг-эндпоинт отправляются только тексты из AI Available vault'ов с включённым RAG.
Без настроенных эмбеддингов (или при выключенном RAG vault'а) `search` работает как текстовый и
сообщает об этом в поле `note`.

## Подключение MCP-клиентов

Endpoint: `http://HOST:8765/mcp`, авторизация `Authorization: Bearer <mcp-токен>`.
Для ассистента достаточно операций `list,search,read`; `write` выдавайте, только если он должен
предлагать правки (они всё равно применяются плагином, а не сервером). Текст заметок в ответах
MCP помечен как недоверенные данные: модель не должна исполнять инструкции из заметок.

```bash
claude mcp add --transport http obsi http://HOST:8765/mcp --header "Authorization: Bearer obsi_..."
```

Claude Desktop (через `claude_desktop_config.json`, мост `mcp-remote`):

```json
{ "mcpServers": { "obsi": { "command": "npx",
  "args": ["mcp-remote", "http://HOST:8765/mcp", "--header", "Authorization: Bearer obsi_..."] } } }
```

Либо добавьте сервер как custom connector в настройках клиента, если он поддерживает заголовок
Authorization.

## Устройство

`config`, `db` (sqlite WAL, миграции по `user_version`), `auth`, `vaults`, `storage`, `ai_store`,
`changes`, `rag`, `mcp`, `app` (REST + сборка), `cli`. Модули связаны хуками: `ai_store` сообщает
`rag` о PUT/DELETE/clear (удаление из индекса синхронное), `vaults` вызывает purge при удалении vault'а.
Чанки и FTS пишутся синхронно при публикации, эмбеддинги догоняет фоновый воркер
(батчи по 32, таймаут 60 с, при ошибке повтор с backoff, сервер не падает).
