# Аудит server-side: obsi-mcp

Дата: 2026-10-07. Объект: локальный исходник `/workspace/obsi-mcp/server` (пакет `obsi_server`, установщики, `docs/`). Метод: белый ящик, сеть не использовалась. Динамические проверки против живого VPS не проводились. Плагин Obsidian в этот репозиторий не входит.

Существующие тесты `tests.test_security_limits` и `tests.test_body_limit` проходят (unittest). `tests.test_users` из корня репозитория не импортируется: нет модуля `helpers` на `PYTHONPATH`.

## Что уже сделано правильно

Это не список «можно не трогать», а границы, которые ломать при фиксах не нужно.

- Секреты токенов и коды приглашений в БД только как SHA-256; пароль — scrypt с солью и `secrets.compare_digest`.
- SQL везде с параметрами. Имя файла на диске — SHA-256 ключа, путь AI Available режется в `norm_path` (`..`, абсолютный путь, NUL).
- Чужой vault не читается: `vault_access` и проверка владельца при выдаче user-токена. MCP-токен не ходит в REST хранилища, device-токен не ходит в `/mcp`.
- Лимиты логина, регистрации и токена лежат в SQLite, а не в памяти процесса. `X-Forwarded-For` принимается только от peer `127.0.0.1` / `::1`.
- Тело режется до парсера FastAPI. Каталог данных обязан быть `0700`, файл БД — `0600`.
- Установщик VPS сажает сервис на `127.0.0.1`, пользователь `obsi-mcp`, `NoNewPrivileges`, `ProtectSystem=strict`. S3-ключи пишутся в `/etc/obsi-mcp/s3.env` с режимом `0600`. `data/` в `.gitignore`.
- Правка из MCP попадает в очередь `changes`, сервер сам заметку в vault не записывает.
- FTS-запрос собирается из `\w+` и кавычек, не из сырой строки пользователя.

## Что устранить

Порядок — по ущербу на общем VPS, где уже есть чужие vault'ы.

### 1. High. Произвольный URL эмбеддингов: SSRF и утечка текста заметок

`PUT /api/v1/admin/settings` и CLI `set-embedding` записывают `base_url` как есть (`obsi_server/rag.py`, `set_embedding`, около строки 121). Фоновый воркер и поиск делают `httpx.post(base_url + "/embeddings")` (`rag.py`, `http_embed`, около строки 40). В теле уходят куски AI Available и текст поискового запроса, в заголовке — API-ключ.

Админ и так может выписать себе device-токен и прочитать AI Available. Новый ущерб другой: процесс на VPS начинает ходить в сеть от своего имени. Достаточно `http://169.254.169.254/...` или внутреннего адреса. Редиректы httpx по умолчанию не следует, схема `https` не требуется, частные и link-local адреса не отсекаются.

Сделать:

- Принимать только `https`.
- Резолвить имя и отвергать loopback, link-local, RFC1918, ULA, metadata (`169.254.169.254`, `fd00:ec2::254`). Повторять проверку на каждый connect, не кэшировать «хороший» DNS.
- Запретить редиректы.
- Таймаут оставить, добавить лимит размера ответа.
- В `last_error` и в лог писать код ошибки без URL и тела ответа (`rag.py`, около строк 211 и 248). Сейчас туда попадает `str(exception)`, и это же уходит в `GET /admin/settings`.

### 2. High. Один пользователь может занять диск и память всего процесса

Общий процесс, квот нет.

- `read_body` собирает PUT целиком в `bytearray` до `max_body_bytes` (по умолчанию 200 МиБ, `app.py` около строки 112, `config.py` около строки 21). Параллельные PUT'ы держат это в RAM.
- Markdown в AI Available не уходит в S3 (`ai_store.py`, `offload` только если расширение не `.md`). Файл пишется в SQLite BLOB, затем `index_file` синхронно режет его на чанки в том же запросе.
- `write_note` кладёт content в SQLite в пределах лимита тела MCP (8 МиБ на запрос, до 100 сообщений в batch). Отдельного потолка на очередь нет.
- Семантический поиск читает все эмбеддинги разрешённых vault'ов в память без `LIMIT` (`rag.py`, `_semantic_hits`, около строк 276–284) и только потом берёт top-N. Поиск по большому vault'у раздувает RSS всего сервиса, включая чужих пользователей.
- Лимит токена по умолчанию 6000 запросов в минуту (`config.py`, `sync_requests_per_minute`). Для синхронизации это много, для записи больших тел — нет.

Сделать:

- Квота байт на vault (ciphertext, AI Available, очередь changes) и отказ `413`/`507` до записи.
- Крупные PUT стримить во временный файл с потолком, не держать 200 МиБ на запрос. Ограничить число одновременных больших тел.
- Потолок на одну заметку MCP (разумный отдельный лимит, меньше 8 МиБ) и на число pending changes.
- Поиск: не материализовать все векторы vault'а. Хотя бы батчи с ранним отсечением; лучше отдельный индекс. Жёсткий потолок чанков на vault.
- В unit systemd: `MemoryMax`, `MemoryHigh`, `TasksMax`. Сейчас их нет (`install-vps.sh`, юнит около строки 157).

### 3. Medium. Сессии и приглашения живут, пока их не отзовут руками

`login` каждый раз вставляет новый session-токен (`auth.py`, около строки 150). Поля срока нет. Старые сессии не гасятся. Неиспользованный invite тоже без TTL, API отзыва invite нет.

Украденный `obsi_...` или код из `TOKENS.txt` / вывода установщика работает до ручного revoke. `local.sh` и `install-vps.sh` печатают текст приглашения в stdout; `manage-vps.sh` (`show_credentials`) показывает admin- и MCP-токен в терминале.

Сделать:

- `expires_at` у session-токенов и invite. Проверять его в `authenticate`.
- Потолок живых сессий на пользователя; повторный логин может гасить самые старые.
- `POST /api/v1/admin/invites/{id}/revoke`.
- В установщике не дублировать секрет в журнал сервиса. Токен показывать один раз и не писать его в `ExecStart` или unit.

### 4. Medium. Браузерная поверхность шире, чем нужно серверу синхронизации

- `cors_origins` по умолчанию `["*"]` (`config.py`, строка 24). Cookie нет, заголовок `Authorization` сам не уедет с чужого сайта. Любой origin всё равно может вызвать API, если токен уже оказался в JS на этом origin. Перед веб-клиентом список origin должен быть явным. В проде `*` лучше отвергать при старте.
- FastAPI поднимает `/docs`, `/redoc`, `/openapi.json` без аутентификации. После `setup-https.sh` это публичный каталог маршрутов. В `create_app` выставить `docs_url=None`, `redoc_url=None`, `openapi_url=None` либо закрыть их admin-токеном.
- `GET /api/v1/health` без токена отдаёт версию и флаги фич. Для мониторинга это удобно. На публичном HTTPS оставить короткий `{ok: true}` либо пускать health только с localhost.

### 5. Medium. MCP отдаёт модели сырой текст заметок

`read_note` и `search` возвращают содержимое AI Available как обычный tool result (`mcp.py`). Отдельной пометки «это данные, не инструкции» нет. `write` у MCP-токена позволяет поставить в очередь создание и перезапись `.md`. Сервер сам файл не применяет: устройство должно подтвердить (`changes.py`, описание в `docs/ARCHITECTURE.md`).

Если плагин когда-нибудь начнёт ack без вопроса пользователя, инструкция внутри заметки станет записью в vault. Этот репозиторий плагин не содержит, поведение ack надо проверить там.

Сделать на сервере:

- В текст tool result добавлять устойчивую обёртку: содержимое заметки — данные.
- Не выдавать MCP-токенам `write` по умолчанию. В CLI и в `POST /tokens` пустой `--ops` уже не даёт прав; в документации для ассистента явно рекомендовать `list,search,read`.
- В объекте change оставить `token_id`, чтобы плагин мог показать, кто поставил правку. Сейчас в `_obj` наружу уходит `token_name`, не id (`changes.py`).

### 6. Medium. Зависимости не закреплены

`pyproject.toml`: `fastapi`, `uvicorn`, `httpx` без версий и без хешей. `install-vps.sh` ставит дерево через `pip install --upgrade` локального каталога. Повторный запуск на той же машине может привезти другой набор транзитивных пакетов.

Сделать: зафиксировать версии (lock-файл) и ставить прод из lock, не из «самого свежего» PyPI на каждый install.

### 7. Low. Добить мелочи, пока трогаете auth

- Неизвестный пользователь в `login` выходит сразу, существующий считает scrypt (`auth.py`, `_verify_password`). По времени ответа видно, есть ли имя. Для отсутствующего пользователя считать scrypt с фиктивным хешем тех же параметров.
- Параметры scrypt берутся из строки в БД (`n`, `r`, `p` через `int`, около строки 82). Штатный API их не задаёт. Ограничить их константами сервера, чтобы порченая строка хеша не превращала логин в нагрузку на CPU.
- `_int_header` ловит только `ValueError`. `int(float("inf"))` даёт `OverflowError` и 500 (`app.py`, около строки 124). Ловить `OverflowError` и отвечать 422.
- Юнит: добавить `PrivateTmp=true`. Порт приложения не публиковать; снаружи только Caddy на 443. Это уже так в `install-vps.sh`, это ограничение надо сохранить.

## Чего в коде нет, и это не дыры

Path traversal в blob-хранилище, SQL-инъекция, подмена vault id клиентом, чтение ciphertext чужим user-токеном, подделка IP через `X-Forwarded-For` с внешнего адреса при текущем `forwarded_allow_ips`. Ключи шифрования vault'ов на сервер не приходят: `storage.py` хранит шифротекст.

## Порядок работ

1. Проверка URL эмбеддингов и урезание `last_error`.
2. Квоты, потолок памяти на PUT и на семантический поиск, `MemoryMax` в unit.
3. Срок жизни сессии и invite, отзыв invite. Заодно поправить миграцию `is_session` (пункт 8).
4. Закрыть `/docs`, убрать CORS `*`.
5. Обёртка MCP-ответов, потолок `read_note`, дефолт без `write`.
6. Lock зависимостей, отпечаток SSH-ключа при первом подключении, мелкие правки login/header и CLI `--api-key`.

## Дополнение

Повторная сверка с кодом. Ниже только то, чего не было в пунктах 1–7, либо уточнение фикса.

### 8. Medium. Миграция `is_session` повышает делегированный токен

`obsi_server/db.py`, миграция около строки 70:

```sql
UPDATE tokens SET is_session=1 WHERE user_id IS NOT NULL AND name LIKE 'user:%';
```

Сессии логина и правда называются `user:` + имя. Имя делегированного токена выбирает пользователь. Если до этой миграции такой токен уже был, после обновления он получает обход грантов владельца: все vault'ы аккаунта, создание vault и `/tokens`. Новые токены из `create_user_token` остаются `is_session=0`. Свежая база не затронута.

Исправить миграцию: помечать сессией только строку, которую создали login/register (имя равно `user:` + username этого пользователя, одна такая строка), а не любой префикс `user:`.

### 9. Medium. `set-embedding` без ключа затирает сохранённый ключ

`cli.py`: `--api-key` имеет `default=""`. `set_embedding` пишет значение, если оно не `None` (`rag.py`, около строки 125). Пустая строка проходит. Повторный запуск с новым URL и без флага стирает ключ в `settings`. Сам ключ ещё и виден в `ps` и в истории shell.

Читать ключ из файла `0600` или с tty. Если флаг не передан, передавать `None`.

### 10. Medium. Два PUT одного ключа не атомарны

`storage.py` `put` (около строк 97–134): старый backend читается, файл или S3 пишется, строка обновляется, старая копия удаляется. Это не одна транзакция и не один lock на `(vault_id, key)`. Два device с `write` на тот же ключ могут оставить строку `local` после `unlink` или `s3` после удаления объекта. Это порча одного vault, не чтение чужого.

Держать lock на пару vault+key до конца замены. Удалять старый backend только после успешного условного update.

### 11. Medium. Первое SSH-подключение принимает ключ хоста само

`manage-vps.sh`, `build_ssh_opts`, около строки 258: `StrictHostKeyChecking=accept-new`. Дальше мастер просит пароль SSH и может дойти до sudo и установки. Позже смена ключа проверяется. Первое соединение — нет.

Перед паролем показать отпечаток и ждать подтверждения, что он совпал с панелью хостера. Ключ деплоя создаётся с `-N ''` (около строки 393): для автоматизации это обычно, файл должен оставаться `0600`, пароль на ключ лучше спросить.

### Уточнения к уже записанным пунктам

- В фикс URL эмбеддингов добавить `trust_env=False` у httpx, иначе `HTTP_PROXY` процесса тоже уводит запрос. `follow_redirects` оставить выключенным явно.
- У `read_note` нет потолка: без `end_line` уходит весь текст, картинка уходит целиком в base64 (`mcp.py`, `read_note`). Поиск при этом режет сниппет до 300 символов. Ограничить строки и байты ответа, большой range требовать явно.
- На ответы login/register/create token поставить `Cache-Control: no-store`.
- В `put_object` включать SSE (`AES256` или KMS). IAM ограничить префиксом бакета. `ACL=private` на бакетах без ACL не ставить.
- `chunk_chars` / `chunk_overlap` сверху не ограничены (`vaults.py`, `update`). Это admin-only, но реиндекс может съесть память. Потолок на `chunk_chars`, overlap строго меньше размера чанка.
- `login` не режет пароль порогом 12..1024, в отличие от `register`. Резать до scrypt. На неизвестное имя считать фиктивный scrypt (это уже в пункте 7).
- В `.gitignore` есть только `data/` и `obsi-data/`. Добавить `.env` и корневой `TOKENS.txt`, чтобы секрет мимо каталога `data/` не попал в коммит. Текущий `data/TOKENS.txt` в git не входит.
