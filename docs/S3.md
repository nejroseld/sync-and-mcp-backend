# S3 attachment offload

The server can keep large encrypted sync attachments and AI Available attachments in
S3 compatible object storage. Markdown notes remain local. Since the plugin encrypts
sync file names, uploads must carry
`X-Obsi-Markdown: true` for notes or `X-Obsi-Markdown: false` for attachments. If
the header is missing, the server keeps the blob locally because it cannot safely
infer the original extension.

Offload applies only when the attachment is larger than `s3_threshold_mb` (default
10 MiB). Configure S3 with the `s3` extra (`pip install 'obsi-server[s3]'`) and:

```toml
[server]
s3_bucket = "my-obsi-blobs"
s3_region = "eu-central-1"
s3_endpoint = "https://s3.example.net" # optional for AWS S3
s3_prefix = "obsi"                    # optional
s3_threshold_mb = 10
```

Equivalent environment variables are `OBSI_S3_BUCKET`, `OBSI_S3_REGION`,
`OBSI_S3_ENDPOINT`, `OBSI_S3_PREFIX`, and `OBSI_S3_THRESHOLD_MB`. AWS credentials
use the standard boto3 credential chain. An attachment that exceeds the threshold
without a configured bucket fails with a clear server error rather than being stored
locally against the configured policy.

The VPS installer installs the base dependencies. To enable S3 on that installation,
install boto3 into its environment (`sudo /opt/obsi-mcp/venv/bin/python -m pip install boto3`)
and add the S3 settings to the service environment before
restarting. Keep the bucket private and allow the server to put, get, and delete
objects under its configured prefix.

Sync object keys are derived from the vault id and a SHA-256 digest of the encrypted
logical key. AI Available attachment keys use the vault id, path digest, and content
hash. The database records each file's backend, so reads, overwrites, deletes,
and vault purges can locate and clean up the remote object. AI Available files are
plaintext by design: if published to S3, the object is plaintext too. Configure
bucket access accordingly.
