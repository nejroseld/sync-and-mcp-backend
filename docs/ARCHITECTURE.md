# Архитектура сервера obsi-mcp

Сервер хранит зашифрованные файлы для синхронизации, отдельно принимает разрешённые устройством файлы в AI Available и предоставляет доступ к ним через MCP. Контракт HTTP и MCP описан в [API.md](API.md).

`obsi_server/app.py` собирает REST API. `auth.py` управляет токенами, приглашениями, пользователями и грантами для vault'ов. Пароли хранятся как scrypt-хэши, приглашения — как SHA-256-хэши, токены — как SHA-256-хэши. Таблица vault'ов связывает пользовательские vault'ы с владельцем; старые vault'ы остаются без владельца и доступны по прежним грантам. `storage.py` хранит шифротекст, не имея ключей от vault'ов. `ai_store.py` хранит опубликованные открытым текстом файлы. Вложения больше порога S3 в обоих хранилищах выгружаются в объектное хранилище; расположение отмечено в SQLite, подробности в [S3.md](S3.md). `changes.py` ведёт очередь правок от MCP; устройство подтверждает их применение. `rag.py` поддерживает FTS и необязательные эмбеддинги. `mcp.py` реализует инструменты для MCP-клиентов. `cli.py` запускает сервер и административные команды. База SQLite и локальные blob'ы находятся в каталоге данных.

Плагин Obsidian живёт в отдельном репозитории и обращается к серверу по HTTP. Правила публикации и ключи шифрования находятся на устройстве; сервер их не получает.
